## Dev Notes

### Architecture Context

This story implements a **schema consolidation** that:
1. Renames the schema from `health_companion` to `vt_saas` (generic, template-friendly)
2. Adds new tables for the Vercel AI SDK chat implementation
3. Adds optional Mem0 memory storage tables
4. Abandons the old `health_companion` schema (no migration, fresh start)

**Schema Strategy:**
- **Old Schema:** `health_companion` (app-specific, abandoned)
- **New Schema:** `vt_saas` (generic, template-ready)
- **Migration Approach:** Fresh start - create new schema, don't migrate old data
- **Rationale:** Clean slate for template users, simpler than data migration

### Current Schema Structure

**Before (health_companion schema):**
- `threads` - Dify chat threads
- `user_preferences` - User settings
- `admin_audit_log` - Admin actions
- `feedback` - User feedback

**After (vt_saas schema):**
- `threads` - Dify chat threads (unchanged)
- `user_preferences` - User settings (unchanged)
- `admin_audit_log` - Admin actions (unchanged)
- `feedback` - User feedback (unchanged)
- `vercel_conversations` - NEW: Vercel AI SDK conversations
- `vercel_messages` - NEW: Vercel AI SDK messages
- `mem0_memories` - NEW: Mem0 memory storage
- `memory_extraction_jobs` - NEW: Async memory extraction

### New Table Specifications

#### vercel_conversations

Purpose: Store Vercel AI SDK chat conversations (parallel to Dify `threads` table)

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| id | uuid | PRIMARY KEY | Auto-generated |
| userId | uuid | NOT NULL | Owner of conversation |
| title | text | NULLABLE | Auto-generated or user-set |
| lastMessagePreview | text | NULLABLE | For sidebar display |
| archived | boolean | DEFAULT false | Soft delete |
| createdAt | timestamp | DEFAULT now() | Creation time |
| updatedAt | timestamp | DEFAULT now() | Last activity |

**Indexes:**
- `idx_vercel_conversations_user_id` - Fast user conversation lookup
- `idx_vercel_conversations_user_archived` - Fast active conversation filtering

#### vercel_messages

Purpose: Store individual messages within Vercel conversations

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| id | uuid | PRIMARY KEY | Auto-generated |
| conversationId | uuid | NOT NULL, FK | References vercel_conversations |
| role | text | NOT NULL | 'user' \| 'assistant' \| 'system' |
| content | text | NOT NULL | Message text |
| tokenCount | integer | NULLABLE | For cost tracking |
| latencyMs | integer | NULLABLE | For performance monitoring |
| createdAt | timestamp | DEFAULT now() | Message time |

**Indexes:**
- `idx_vercel_messages_conversation_id` - Fast message lookup by conversation
- `idx_vercel_messages_created_at` - Chronological sorting

**Foreign Key:**
- `conversationId` → `vercel_conversations.id` (CASCADE on delete)

#### mem0_memories

Purpose: Store extracted facts/preferences from conversations (Mem0 integration)

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| id | uuid | PRIMARY KEY | Auto-generated |
| userId | uuid | NOT NULL | Memory owner |
| conversationId | uuid | NULLABLE | Source conversation |
| memoryText | text | NOT NULL | Extracted fact/preference |
| memoryType | text | NULLABLE | 'fact' \| 'preference' \| 'context' |
| metadata | jsonb | NULLABLE | Additional context |
| createdAt | timestamp | DEFAULT now() | Extraction time |
| updatedAt | timestamp | DEFAULT now() | Last update |

**Indexes:**
- `idx_mem0_memories_user_id` - Fast user memory retrieval
- `idx_mem0_memories_conversation_id` - Memory source tracking

#### memory_extraction_jobs

Purpose: Track async memory extraction jobs (background processing)

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| id | uuid | PRIMARY KEY | Auto-generated |
| conversationId | uuid | NOT NULL | Conversation to process |
| status | text | NOT NULL | 'pending' \| 'processing' \| 'completed' \| 'failed' |
| errorMessage | text | NULLABLE | Failure reason |
| createdAt | timestamp | DEFAULT now() | Job queued time |
| completedAt | timestamp | NULLABLE | Job finished time |

**Indexes:**
- `idx_memory_jobs_conversation_id` - Job lookup by conversation
- `idx_memory_jobs_status` - Pending job queue
- `idx_memory_jobs_created_at` - Job age tracking

### Key Implementation Notes

1. **Schema Rename Pattern**:
   ```typescript
   // Before
   export const healthCompanionSchema = pgSchema('health_companion');

   // After
   export const vtSaasSchema = pgSchema('vt_saas');
   ```

2. **Table Definition Pattern**:
   ```typescript
   export const vercelConversations = vtSaasSchema.table(
     'vercel_conversations',
     {
       id: uuid('id').defaultRandom().primaryKey(),
       // ... columns
     },
     table => ({
       userIdIdx: index('idx_vercel_conversations_user_id').on(table.userId),
       // ... indexes
     }),
   );
   ```

3. **Foreign Key Pattern**:
   ```typescript
   export const vercelMessages = vtSaasSchema.table(
     'vercel_messages',
     {
       conversationId: uuid('conversation_id')
         .notNull()
         .references(() => vercelConversations.id, { onDelete: 'cascade' }),
       // ... other columns
     },
   );
   ```

4. **Import Update Pattern**:
   ```typescript
   // Before
   import { healthCompanionSchema } from '@/models/Schema';
   const { threads } = healthCompanionSchema;

   // After
   import { vtSaasSchema } from '@/models/Schema';
   const { threads } = vtSaasSchema;
   ```

5. **Drizzle Migration**:
   - Auto-generated by `npm run db:generate`
   - Auto-applied on next DB interaction (no manual run needed)
   - For Edge runtime: disable auto-migration, run manually

### Project Structure Notes

**Alignment:**
- Follows Drizzle ORM conventions
- Maintains consistent index naming (`idx_{table}_{column}`)
- Uses project-wide `vt_saas` schema namespace
- Prepares for both Dify and Vercel chat implementations

**Naming Conventions:**
- Schema: `vtSaasSchema` (camelCase variable)
- Schema name: `vt_saas` (snake_case SQL)
- Tables: `vercelConversations` (camelCase variable), `vercel_conversations` (snake_case SQL)
- Indexes: `idx_{table}_{column}` (snake_case)

**Database Strategy:**
- **Development:** PGlite (local, in-memory)
- **Production:** PostgreSQL (Prisma Postgres or any provider)
- **Migrations:** Auto-applied on app start (configurable)

- Users can manually migrate if needed
