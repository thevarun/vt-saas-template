## Configuration

### Environment Variables

**For Dify Chat**:
```bash
# Server-side (required)
DIFY_API_URL=https://api.dify.ai/v1
DIFY_API_KEY=your_api_key

# Client-side (for UI detection only)
NEXT_PUBLIC_DIFY_API_URL=https://api.dify.ai/v1
```

**For Vercel AI SDK Chat**:
```bash
# Server-side (required)
OPENAI_API_KEY=sk-...
# OR
ANTHROPIC_API_KEY=sk-ant-...

# Client-side (for UI detection only)
NEXT_PUBLIC_OPENAI_API_KEY=configured
# OR
NEXT_PUBLIC_ANTHROPIC_API_KEY=configured
```

**Note**: The NEXT_PUBLIC vars are NOT actual API keys. They're just flags for the UI to detect which chat options to show. Actual API keys remain server-side only.

## Technical Notes

### Architecture Decisions

1. **Public Config Detection**: Used NEXT_PUBLIC_ vars for client-side detection without exposing API keys
2. **Selection Page vs Redirect**: Chose selection page for better UX and consistency
3. **Dynamic Navigation**: Navigation items built at render time based on config
4. **Icon Differentiation**: MessageSquare (Dify) vs Sparkles (Vercel) for visual distinction

### Edge Cases Handled

1. **Neither configured**: Shows setup message
2. **Only one configured**: Still shows selection page with disabled card
3. **Mid-session config change**: Requires dev server restart (expected)
4. **Locale changes**: All text properly translated

### Security Considerations

1. ✅ API keys never exposed to client
2. ✅ NEXT_PUBLIC_ vars contain no sensitive data
3. ✅ Configuration check happens server-side for page rendering
4. ✅ Middleware protects both chat routes
