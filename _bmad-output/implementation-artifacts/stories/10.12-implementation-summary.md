## Technical Decisions

### Decision 1: Separate Guides vs Single Guide

**Chose:** Three separate guides

**Rationale:**
- Users typically want to remove one specific implementation
- Separate guides are easier to follow without cognitive overload
- Each guide is self-contained (can be used standalone)
- Reduces confusion about what to delete

**Tradeoff:** Some duplication in common sections (verification, troubleshooting)

---

### Decision 2: Include Line Numbers in Code References

**Chose:** Include approximate line numbers for Schema.ts

**Rationale:**
- Helps users find exact code to remove
- Reduces errors from removing wrong code
- Faster to locate in large files

**Tradeoff:** Line numbers may shift if file is modified; mitigated by providing clear code blocks

---

### Decision 3: Auto-hide vs Manual Removal of Navigation

**Chose:** Document both options, recommend auto-hide

**Rationale:**
- Navigation links auto-hide when env vars are missing (via chatConfig)
- Manual removal is cleaner but requires code changes
- Auto-hide is safer (no code modification needed)

**Result:** Guides show manual removal as optional cleanup

---

### Decision 4: Data Export Instructions

**Chose:** Provide SQL COPY commands for data backup

**Rationale:**
- Users may want conversation history for legal/compliance
- Easy to execute (single SQL command)
- CSV format is portable

**Tradeoff:** Requires database access; mitigated by marking as optional

---

### Decision 5: Troubleshooting Depth

**Chose:** Cover 4-5 most common issues per guide

**Rationale:**
- Based on typical removal/migration issues:
  - Import errors (most common)
  - Cache issues (common in Next.js)
  - Database migration failures
  - Type errors
- Each issue has clear cause and solution

**Avoided:** Exhaustive troubleshooting (would make guides too long)

## Lessons Learned

### What Went Well

1. **Comprehensive code audit** - Reviewing actual files prevented documentation errors
2. **Consistent structure** - Template made writing easier and guides more usable
3. **Safety focus** - Warnings and verification prevent user mistakes
4. **Cross-linking** - Guides form a cohesive documentation set

### What Could Improve

1. **Live testing** - Would catch any missed edge cases
2. **User feedback** - Real users trying guides would reveal unclear steps
3. **Automation** - Manual removal is error-prone; scripts would help

### Best Practices Established

1. Always include data backup recommendations
2. Provide verification at each major step
3. Show both what to remove AND what to keep
4. Include troubleshooting for predictable issues
5. Cross-reference related documentation
