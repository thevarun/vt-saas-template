# Story 10.6: Mem0 Memory Integration (Opt-in)

Status: completed

## Story

As a template user (developer),
I want automatic memory extraction from conversations,
so that the AI can remember facts about users across sessions.

## Acceptance Criteria

1. **Given** `ENABLE_MEM0=true`
   **When** a conversation completes
   **Then** a memory extraction job is queued
   **And** job status is 'pending' in database

2. **Given** a pending extraction job
   **When** the extraction worker runs
   **Then** memories are extracted via Mem0 API
   **And** memories are stored in `mem0_memories` table
   **And** job status updates to 'completed'

3. **Given** an active conversation
   **When** the user sends a message
   **Then** relevant memories are fetched
   **And** memories are injected into system prompt context

4. **Given** `ENABLE_MEM0=false` (default)
   **When** a conversation occurs
   **Then** no memory extraction happens
   **And** no errors occur
   **And** chat functions normally

5. **Given** a memory extraction failure
   **When** the job fails
   **Then** job status is 'failed'
   **And** error message is recorded
   **And** other jobs continue processing

## Dev Notes

### Architecture Context

Mem0 is a **memory layer for AI applications** that provides:
- Automatic fact extraction from conversations
- Semantic memory search
- User preference tracking
- Context persistence across sessions

**Integration Strategy:**
- **Opt-in Feature**: Disabled by default for privacy
- **Async Processing**: Memory extraction happens in background (non-blocking)
- **Job Queue Pattern**: Jobs queued immediately, processed by cron worker
- **Graceful Degradation**: Chat works perfectly without Mem0

**Key Design Decisions:**
1. **Optional Feature**: Chat works without Mem0 (disabled by default)
2. **Privacy-First**: Users must explicitly enable (developer decision)
3. **Non-Blocking**: Memory operations never block chat responses
4. **Fire-and-Forget**: Job queueing is async, doesn't wait for completion
5. **Separate Tables**: Mem0 memories isolated in dedicated schema

### Mem0 Client Implementation

**Singleton Pattern:**

```typescript
// src/libs/mem0/client.ts
import { MemoryClient } from 'mem0ai';
import { logger } from '@/libs/Logger';
import { MEM0_CONFIG, isEnabled } from './config';

let mem0Client: MemoryClient | null = null;
let disabledWarningLogged = false;

/**
 * Get Mem0 client instance (singleton).
 * Returns null if Mem0 is disabled.
 */
export function getMem0Client(): MemoryClient | null {
  if (!isEnabled()) {
    if (!disabledWarningLogged) {
      logger.info('Mem0 disabled - skipping memory features');
      disabledWarningLogged = true;
    }
    return null;
  }

  if (!mem0Client) {
    try {
      mem0Client = new MemoryClient({
        apiKey: MEM0_CONFIG.apiKey!,
      });
    } catch (error) {
      logger.error({ error }, 'Failed to initialize Mem0 client');
      return null;
    }
  }

  return mem0Client;
}

export function isMem0Enabled(): boolean {
  return isEnabled();
}
```

### Job Queue Pattern

**Queue Function:**

```typescript
// src/libs/mem0/queue.ts
import { logger } from '@/libs/Logger';
import { createMemoryJob } from '@/libs/queries/memoryJobs';
import { isMem0Enabled } from './client';

export async function queueMemoryExtraction(
  conversationId: string,
): Promise<void> {
  if (!isMem0Enabled()) {
    return; // Skip if disabled
  }

  try {
    await createMemoryJob(conversationId);
    logger.info({ conversationId }, 'Memory extraction job queued');
  } catch (error) {
    logger.error({ error, conversationId }, 'Failed to queue memory job');
    // Don't throw - this should never block chat
  }
}
```

**Worker Function:**

```typescript
// src/libs/mem0/worker.ts
import { logger } from '@/libs/Logger';
import { getMem0Client, isMem0Enabled } from './client';
import {
  getPendingJobs,
  updateJobStatus,
} from '@/libs/queries/memoryJobs';
import { getMessagesByConversation } from '@/libs/queries/vercelMessages';
import { createMemory } from '@/libs/queries/mem0Memories';

export async function processMemoryExtractionJobs(): Promise<void> {
  if (!isMem0Enabled()) {
    logger.info('Mem0 disabled - skipping job processing');
    return;
  }

  const client = getMem0Client();
  if (!client) {
    logger.warn('Mem0 client not available');
    return;
  }

  const jobs = await getPendingJobs();
  logger.info({ jobCount: jobs.length }, 'Processing memory extraction jobs');

  for (const job of jobs) {
    try {
      await updateJobStatus(job.id, 'processing');

      // Fetch conversation messages
      const messages = await getMessagesByConversation(job.conversationId);

      // Extract memories via Mem0 API
      const memories = await client.add(
        messages.map(m => ({
          role: m.role,
          content: m.content,
        })),
        {
          user_id: messages[0]?.userId, // Assumes messages have userId
        },
      );

      // Store memories in database
      for (const memory of memories) {
        await createMemory(
          messages[0]?.userId,
          job.conversationId,
          memory.text,
          memory.type,
          memory.metadata,
        );
      }

      await updateJobStatus(job.id, 'completed');
      logger.info({ jobId: job.id, memoryCount: memories.length }, 'Job completed');
    } catch (error) {
      logger.error({ error, jobId: job.id }, 'Job failed');
      await updateJobStatus(job.id, 'failed', error.message);
    }
  }
}
```

### Memory Retrieval and Injection

**Retrieval Function:**

```typescript
// src/libs/mem0/retrieval.ts
import { logger } from '@/libs/Logger';
import { getMem0Client, isMem0Enabled } from './client';

export async function getRelevantMemories(
  userId: string,
  query: string,
): Promise<string[]> {
  if (!isMem0Enabled()) {
    return [];
  }

  const client = getMem0Client();
  if (!client) {
    return [];
  }

  try {
    const memories = await client.search(query, {
      user_id: userId,
      limit: 5,
    });

    return memories.map(m => m.text);
  } catch (error) {
    logger.error({ error, userId }, 'Failed to fetch memories');
    return []; // Return empty on error (graceful degradation)
  }
}
```

### Cron Endpoint Pattern

**API Route:**

```typescript
// src/app/api/cron/memory-extraction/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { processMemoryExtractionJobs } from '@/libs/mem0/worker';
import { logger } from '@/libs/Logger';

export async function GET(request: NextRequest): Promise<NextResponse> {
  // Validate cron secret (for security)
  const authHeader = request.headers.get('authorization');
  const expectedAuth = `Bearer ${process.env.CRON_SECRET}`;

  if (authHeader !== expectedAuth) {
    return NextResponse.json(
      { error: 'Unauthorized' },
      { status: 401 },
    );
  }

  try {
    await processMemoryExtractionJobs();
    return NextResponse.json({ success: true });
  } catch (error) {
    logger.error({ error }, 'Cron job failed');
    return NextResponse.json(
      { error: 'Job processing failed' },
      { status: 500 },
    );
  }
}
```

### Error Handling

**Graceful Degradation Pattern:**

1. Check if enabled BEFORE any Mem0 operation
2. Return early/skip when disabled
3. Log info message once per app lifecycle
4. Continue without memory features if disabled
5. Catch errors during all Mem0 API calls
6. Log errors to Sentry (don't throw)
7. Ensure chat never blocked by memory operations

**Error Scenarios:**

| Scenario | Handling |
|----------|----------|
| Mem0 disabled | Skip all operations, no warnings in logs |
| Missing API key | Skip operations, log warning once |
| Invalid API key | Catch error, log to Sentry, continue |
| Mem0 API down | Job fails, retries later, chat works |
| Network timeout | Job fails, retries later, chat works |
| Job processing error | Mark job as failed, log error, continue |

### Completion Notes List

1. **Dependency Installation**: Used --legacy-peer-deps due to @types/pg version conflict between project and mem0ai package
2. **Graceful Degradation**: All Mem0 operations check `isMem0Enabled()` first and return gracefully when disabled
3. **Fire-and-Forget Pattern**: Memory extraction jobs are queued async and don't block chat responses
4. **Error Isolation**: Worker processes jobs independently - errors in one job don't stop others
5. **Privacy-First**: Feature disabled by default (ENABLE_MEM0=false) with comprehensive privacy documentation
6. **Type Safety**: All modules include proper TypeScript types using Mem0 SDK type definitions
7. **Sentry Integration**: All errors logged to Sentry with context for monitoring
8. **Cron Configuration**: Vercel cron runs every 5 minutes, secured with CRON_SECRET
9. **Memory Injection**: Relevant memories fetched before each chat request and injected into system prompt
10. **Future Enhancements**: Retry logic with exponential backoff and caching layer noted as future improvements
