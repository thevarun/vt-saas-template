## API Endpoints

### GET /api/chat/vercel/conversations
**Purpose:** List user's conversations with pagination

**Query Parameters:**
- `limit` (optional): Max conversations to return (default: 50, max: 100)
- `offset` (optional): Number of conversations to skip (default: 0)

**Response:**
```json
{
  "conversations": [
    {
      "id": "uuid",
      "userId": "uuid",
      "title": "string | null",
      "lastMessagePreview": "string | null",
      "archived": false,
      "createdAt": "2024-01-01T00:00:00.000Z",
      "updatedAt": "2024-01-01T00:00:00.000Z"
    }
  ],
  "total": 42
}
```

**Status Codes:**
- 200: Success
- 401: Unauthorized (no valid session)
- 500: Internal server error

## Security Features

### User Ownership Validation
- All endpoints validate user session via Supabase auth
- Database queries filter by `userId` automatically
- RLS (Row Level Security) ensures users only access their own data

### Security Through Obscurity
- Returns **404 Not Found** (not 403 Forbidden) when:
  - Conversation doesn't exist
  - Conversation exists but belongs to another user
- Prevents user enumeration attacks
- Attackers cannot distinguish between "exists but forbidden" vs "doesn't exist"

### Cascade Delete
- Deleting a conversation automatically deletes all associated messages
- Implemented at database level via `onDelete: 'cascade'`
- Transaction is atomic (all or nothing)

## Pagination Strategy

**Approach:** Database-level pagination using Drizzle ORM

**Implementation:**
```typescript
const query = db
  .select()
  .from(vercelConversations)
  .where(eq(vercelConversations.userId, userId))
  .orderBy(desc(vercelConversations.updatedAt))
  .limit(limit)
  .offset(offset);
```

**Benefits:**
- Efficient for small to medium datasets
- Simple implementation
- Consistent with existing patterns
- Can scale to cursor-based pagination if needed
