# Story 10.1: Rename Existing Chat Route

Status: ready-for-dev

## Story

As a template user (developer),
I want the existing Dify chat to be at `/chat/dify`,
so that both chat implementations have clear, distinct routes.

## Acceptance Criteria

1. **Given** the existing chat implementation at `/chat`
   **When** I navigate to `/chat/dify`
   **Then** the Dify chat interface loads correctly
   **And** the thread list displays my conversations
   **And** I can navigate to `/chat/dify/[threadId]` for specific threads

2. **Given** the route rename
   **When** I navigate to the old `/chat` route
   **Then** I am redirected to `/chat/dify` OR see a chat selection page

3. **Given** the navigation component
   **When** I view the navigation
   **Then** the chat link points to `/chat/dify` with clear labeling (e.g., "Chat (Dify)")

4. **Given** the middleware configuration
   **When** I review protected paths
   **Then** `/chat` and all sub-routes remain protected (requires authentication)

5. **Given** the API route structure
   **When** I review the chat API
   **Then** `/api/chat` remains unchanged (or is renamed to `/api/chat/dify` with documentation)

6. **Given** all E2E tests referencing `/chat`
   **When** I run the test suite
   **Then** all tests pass with updated route references

## Dev Notes

### Architecture Context

This story implements a **pure refactoring** - no logic changes, only route structure reorganization.

**Current Structure (Before):**
```
src/app/[locale]/(auth)/chat/
├── page.tsx              # Main chat page
├── [threadId]/page.tsx   # Thread detail
└── error.tsx             # Error boundary
```

**Target Structure (After):**
```
src/app/[locale]/(auth)/chat/
├── page.tsx              # NEW: Redirect to /chat/dify
├── dify/
│   ├── page.tsx          # MOVED: Main chat page
│   ├── [threadId]/page.tsx # MOVED: Thread detail
│   └── error.tsx         # MOVED: Error boundary
└── vercel/ (future)      # Reserved for Story 10.7
```

### Key Implementation Notes

1. **No Import Changes Needed**: Project uses absolute imports with `@/` prefix, so moving files doesn't break imports

2. **Next.js 15 Patterns**:
   - Use `redirect()` from `next/navigation` for /chat → /chat/dify redirect
   - Dynamic params are async: `const { threadId } = await props.params`

3. **Middleware Behavior**:
   - Current: `protectedPaths.some(path => pathname.includes(path))`
   - With `'/chat'` in array, covers all sub-routes automatically
   - No changes needed

4. **API Route Decision**:
   - **Recommendation**: Keep `/api/chat` as-is with documentation comment
   - **Rationale**: Less change, API routes aren't user-facing, simpler for this story
   - **Alternative**: Rename to `/api/chat/dify` (more explicit but more work)

5. **Testing Strategy**:
   - Update E2E tests first (faster feedback loop)
   - Then update component tests
   - Manual testing last (verify all pieces together)
