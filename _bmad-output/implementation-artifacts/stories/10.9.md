# Story 10.9: Navigation & Showcase Update

Status: pending

## Story

As a template user (developer),
I want both chat implementations accessible from navigation,
so that I can easily compare and test both options.

## Acceptance Criteria

1. **Given** the main navigation
   **When** I view the chat section
   **Then** I see options for both "Chat (Dify)" and "Chat (AI SDK)"
   **And** labels clearly differentiate the two

2. **Given** no chat configuration
   **When** Dify is not configured but Vercel AI SDK is
   **Then** only the configured option is shown
   **And** unconfigured option shows "Setup Required" or is hidden

3. **Given** the dashboard or landing page
   **When** I look for chat features
   **Then** both options are discoverable
   **And** brief descriptions explain the difference

4. **Given** the navigation component
   **When** I update the routes
   **Then** old `/chat` links are updated to `/chat/dify`
   **And** new `/chat/vercel` links are added
   **And** all navigation items are properly translated

5. **Given** configuration detection
   **When** environment variables are checked
   **Then** Dify requires `DIFY_API_URL` and `DIFY_API_KEY`
   **And** Vercel requires `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`
   **And** unconfigured options are handled gracefully

## Dev Notes

### Architecture Context

This story completes the dual-chat implementation by making both options discoverable and accessible from the main navigation. The key challenge is conditional rendering based on environment configuration.

**Key Design Decisions:**

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Label Format | "Chat (Dify)" vs "Chat (AI SDK)" | Clear, concise, differentiates by provider |
| Config Detection | Environment variables | Simple, no database checks needed |
| Unconfigured Handling | Hide or show "Setup Required" | Graceful degradation, no broken links |
| Selection Page | Optional, recommended | Better UX than auto-redirect |

### Configuration Detection Pattern

**Server-Side (for SSR pages):**

```typescript
import { getChatConfig } from '@/utils/chatConfig';

export default async function NavigationServerComponent() {
  const config = getChatConfig();

  return (
    <nav>
      {config.dify.configured && (
        <Link href="/chat/dify">Chat (Dify)</Link>
      )}
      {config.vercel.configured && (
        <Link href="/chat/vercel">Chat (AI SDK)</Link>
      )}
    </nav>
  );
}
```

**Client-Side (for client components):**

```typescript
'use client';

import { getPublicChatConfig } from '@/utils/chatConfig';
import { useTranslations } from 'next-intl';

export function NavigationClientComponent() {
  const t = useTranslations('nav');
  const config = getPublicChatConfig();

  return (
    <nav>
      {config.dify.configured && (
        <Link href="/chat/dify">{t('chat_dify')}</Link>
      )}
      {config.vercel.configured && (
        <Link href="/chat/vercel">{t('chat_vercel')}</Link>
      )}
    </nav>
  );
}
```

### Environment Variable Strategy

**Public vs Private:**

| Variable | Scope | Purpose |
|----------|-------|---------|
| `DIFY_API_URL` | Server | Dify API endpoint (private) |
| `DIFY_API_KEY` | Server | Dify API key (private) |
| `NEXT_PUBLIC_DIFY_API_URL` | Public | Config detection only |
| `OPENAI_API_KEY` | Server | OpenAI API key (private) |
| `NEXT_PUBLIC_OPENAI_API_KEY` | Public | Config detection only |

**Note:** Public env vars should NOT contain actual API keys. They're only for config detection. The actual API calls use server-side env vars.

**Recommended Approach:**

Add build-time config detection:

```typescript
// next.config.mjs or build script
const isDifyConfigured = Boolean(process.env.DIFY_API_URL);
const isVercelConfigured = Boolean(process.env.OPENAI_API_KEY);

export default {
  env: {
    NEXT_PUBLIC_CHAT_DIFY_ENABLED: isDifyConfigured,
    NEXT_PUBLIC_CHAT_VERCEL_ENABLED: isVercelConfigured,
  },
};
```

### Chat Selection Page Design

**Option A: Simple Redirect (Easier)**

```typescript
// src/app/[locale]/(auth)/chat/page.tsx
import { redirect } from 'next/navigation';
import { getChatConfig } from '@/utils/chatConfig';

export default async function ChatPage() {
  const config = getChatConfig();

  if (config.dify.configured) {
    redirect('/chat/dify');
  } else if (config.vercel.configured) {
    redirect('/chat/vercel');
  } else {
    // Show setup instructions
    return <ChatSetupInstructions />;
  }
}
```

### Edge Cases

1. **Both Chat Routes Not Configured:**
   - Hide chat section entirely
   - OR show "Setup Required" message
   - Don't break navigation layout

2. **Mid-Session Config Change:**
   - Config is checked at build time or on page load
   - If env vars change, restart dev server
   - Production: Requires redeployment

3. **Direct URL Access:**
   - If user navigates to `/chat/dify` but not configured
   - Show setup message on that page (handled by Stories 10.2 and 10.7)

4. **Localization:**
   - Ensure all labels are translated
   - Test RTL languages if supported
   - Keep labels short for mobile
